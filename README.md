# Vault Ledger — คู่มือติดตั้ง

เว็บเก็บพาสเวิด/รูปภาพส่วนตัว เข้ารหัสฝั่งเบราว์เซอร์ด้วย master password ก่อนส่งขึ้น Supabase
ทำงานได้ทั้งบน PC และมือถือผ่านลิงก์เว็บเดียวกัน (responsive)

ไฟล์ในชุดนี้:
- `index.html` — ตัวเว็บทั้งหมด (auth, เข้ารหัส, จัดการรายการ, ไฟล์แนบหลายไฟล์, export/import พร้อมไฟล์แนบ, auto-lock, ปักหมุด ฯลฯ)
- `supabase-schema.sql` — คำสั่งสร้างตาราง + กฎความปลอดภัย (RLS) สำหรับ Supabase
- `manifest.json` — ไฟล์ประกาศแอป สำหรับฟีเจอร์ "เพิ่มลงหน้าจอหลัก" (PWA)
- `sw.js` — service worker แคชเปลือกแอปให้เปิดเร็วขึ้น (ไม่แคชข้อมูลจริงจาก Supabase)
- `icon-192.png`, `icon-512.png` — ไอคอนแอปสำหรับหน้าจอหลัก

> **สำคัญ:** ต้องอัปโหลดไฟล์ทั้งหมดข้างบน (รวม `manifest.json`, `sw.js`, ไอคอนทั้งสอง) ขึ้น repo เดียวกันกับ `index.html`
> ไม่ใช่แค่ `index.html` อย่างเดียวเหมือนเวอร์ชันก่อน ไม่งั้นฟีเจอร์ "เพิ่มลงหน้าจอหลัก" จะไม่ทำงาน

---

## ขั้นตอนที่ 1 — สร้าง Supabase project

1. เข้า https://supabase.com → เข้าบัญชีเดิมที่เคยใช้ทำเว็บรายรับรายจ่าย
2. กด **New project** ตั้งชื่อ (เช่น `vault-ledger`) เลือก region ใกล้ตัว (เช่น Singapore) ตั้งรหัส database ไว้ (ไม่เกี่ยวกับ master password ของแอป)
3. รอ project สร้างเสร็จ (1-2 นาที)

## ขั้นตอนที่ 2 — รันคำสั่งสร้างตาราง

1. ในเมนูซ้าย เลือก **SQL Editor** → **New query**
2. เปิดไฟล์ `supabase-schema.sql` ที่ให้มา คัดลอกทั้งหมดวางในช่อง
3. กด **Run** — ถ้าสำเร็จจะไม่มี error สีแดง

> **ถ้าเคยสร้าง project นี้ไว้แล้วจากเวอร์ชันก่อนหน้า (มีข้อมูลอยู่แล้ว):**
> ไฟล์ `supabase-schema.sql` เวอร์ชันนี้เพิ่มตาราง `vault_categories` (สำหรับหน้า "จัดการหมวดหมู่"),
> คอลัมน์ `size_bytes` ในตาราง `vault_files` (สำหรับหน้า "พื้นที่จัดเก็บ"),
> และล่าสุดคอลัมน์ `icon_key` ในตาราง `vault_categories` (สำหรับตั้งไอคอนต่อหมวดหมู่) เข้ามาใหม่
> วางไฟล์ทั้งไฟล์แล้วกด Run ซ้ำได้เลย ทุกคำสั่งเขียนแบบ `if not exists` ไม่ทับข้อมูลเดิม ปลอดภัย 100%
> ถ้าลืมรัน SQL ใหม่ แอปยังใช้งานได้ปกติ แค่ยังตั้งไอคอนหมวดหมู่เองไม่ได้ (จะใช้ไอคอนอัตโนมัติจากชื่อ platform แทน)

## ขั้นตอนที่ 3 — สร้าง Storage bucket สำหรับไฟล์แนบ

1. เมนูซ้าย เลือก **Storage** → **New bucket**
2. ตั้งชื่อ bucket ว่า `vault-files` **ตัวพิมพ์เล็กทั้งหมด ตรงตามนี้เป๊ะ**
3. **ปิด** ตัวเลือก "Public bucket" ไว้ (ต้องเป็น private เท่านั้น เพราะไฟล์เข้ารหัสแต่ path ไม่ควรเปิดสาธารณะ)
4. กด Create — policy การเข้าถึง bucket ถูกตั้งไว้แล้วในขั้นตอนที่ 2 (SQL ท้ายไฟล์)

## ขั้นตอนที่ 4 — ปิดการยืนยันอีเมล (ถ้าอยากทดสอบเร็วๆ) — ไม่บังคับ

โดย default Supabase จะให้ผู้สมัครยืนยันอีเมลก่อนใช้งาน ถ้าอยากข้ามตอนทดสอบ:
Authentication → Providers → Email → ปิด "Confirm email" (แนะนำให้เปิดกลับตอนใช้งานจริง)

## ขั้นตอนที่ 5 — เอาค่าเชื่อมต่อมาใส่ในไฟล์ index.html

1. เมนูซ้าย **Project Settings** → **API**
2. คัดลอกค่า **Project URL** และ **anon public** key
3. เปิด `index.html` ด้วยโปรแกรมแก้ไขข้อความ (Notepad, VS Code) ค้นหาบรรทัดนี้ใกล้ๆ ต้น `<script>`:
   ```js
   const SUPABASE_URL = 'YOUR_SUPABASE_URL';
   const SUPABASE_ANON_KEY = 'YOUR_SUPABASE_ANON_KEY';
   ```
4. แทนที่ด้วยค่าจริงของคุณ แล้วเซฟไฟล์

> หมายเหตุ: anon key เป็นคีย์สาธารณะที่ตั้งใจให้ฝังในโค้ดฝั่ง client อยู่แล้ว (ปลอดภัยเพราะมี RLS policy คุมสิทธิ์การเข้าถึงข้อมูลตาม `auth.uid()` ในฐานข้อมูล) — ไม่ใช่คีย์ลับแบบ service_role

## ขั้นตอนที่ 6 — Deploy ขึ้น GitHub Pages

1. สร้าง repo ใหม่บน GitHub (private ก็ได้ เพราะข้อมูลจริงไม่ได้อยู่ในโค้ด)
2. อัปโหลดไฟล์เหล่านี้ขึ้น repo (**ไม่ต้อง**อัปโหลด `.sql`):
   - `index.html` (แก้ไขค่า Supabase แล้ว)
   - `manifest.json`
   - `sw.js`
   - `icon-192.png`
   - `icon-512.png`
3. ไปที่ **Settings → Pages** ของ repo → เลือก branch `main` และ path root → Save
4. รอ 1-2 นาที จะได้ลิงก์แบบ `https://ชื่อผู้ใช้.github.io/ชื่อ repo/`
5. เปิดลิงก์นั้นจากมือถือหรือคอมเครื่องไหนก็ได้ — สมัครบัญชี ตั้ง master password แล้วเริ่มใช้งาน
6. บนมือถือ เปิดลิงก์ด้วย Chrome/Safari แล้วเลือก "เพิ่มลงหน้าจอหลัก" (Add to Home Screen) จะได้ไอคอนแอปเปิดตรงเหมือนแอปจริง

## ข้อควรรู้เรื่องความปลอดภัย

- **master password ไม่เคยถูกส่งขึ้นเซิร์ฟเวอร์และไม่ถูกเก็บที่ไหนเลย** — ถ้าลืมจะกู้ข้อมูลคืนไม่ได้ ไม่มีปุ่ม "ลืมรหัส"
- ปิดแท็บหรือกด "ล็อกวอลต์" แล้วต้องใส่ master password ใหม่ทุกครั้ง (ตั้งใจให้เป็นแบบนี้เพื่อความปลอดภัย)
- ไฟล์สำรอง (export) ที่ดาวน์โหลดออกมายังเข้ารหัสอยู่ด้วย master password เดิม เก็บไว้ที่ไหนก็ได้ (Google Drive, USB) แต่ถ้าไฟล์นั้นหลุด คนอื่นก็ยังต้องรู้ master password ถึงจะเปิดได้
- รหัสผ่านบัญชี (ตอน sign up/login) กับ master password เป็นคนละตัวกันโดยตั้งใจ — รหัสบัญชีแค่คุมว่าใครล็อกอินเข้าเว็บได้ ส่วน master password คุมว่าใครถอดรหัสข้อมูลได้จริง

## สิ่งที่เพิ่มเข้ามาในเวอร์ชันนี้

**ความปลอดภัย**
- Auto-lock: ไม่มีการใช้งาน (ไม่ขยับเมาส์/แตะจอ/พิมพ์) เกิน 5 นาที ระบบล็อกวอลต์ให้อัตโนมัติ
- คัดลอกรหัสผ่านแล้ว clipboard จะถูกล้างอัตโนมัติหลังผ่านไป 25 วินาที (ถ้าไม่มีการคัดลอกอย่างอื่นทับก่อน)
- ตัวเช็คความแข็งแรงรหัสผ่านแสดงผลสดๆ ตอนพิมพ์เอง ไม่ใช่แค่ตอนกด "สุ่ม"

**UX**
- รองรับติดตั้งเป็น PWA — "เพิ่มลงหน้าจอหลัก" ได้จากมือถือ (ดูขั้นตอนที่ 6)
- แนบไฟล์ได้หลายไฟล์ต่อ 1 รายการ ทั้งตอนสร้างใหม่และแก้ไข
- ค้นหาครอบคลุมช่อง Note ด้วยแล้ว ไม่ใช่แค่ platform/username
- ปักหมุดรายการโปรด (ไอคอนหมุดที่แต่ละแถว หรือปุ่มในหน้ารายละเอียด) รายการที่ปักหมุดจะขึ้นบนสุดเสมอ

**ระบบ**
- มี toast แจ้งเตือนถ้ายังไม่เคย export หรือไม่ได้ export มาเกิน 30 วัน (เช็คทุกครั้งที่ปลดล็อกวอลต์ เก็บสถานะไว้ในเบราว์เซอร์เครื่องนั้นๆ)
- ไฟล์สำรอง (export) ตอนนี้รวมไฟล์แนบไปด้วย (เข้ารหัสอยู่เหมือนเดิม) ย้ายเครื่อง/กู้คืนแล้วไฟล์แนบจะติดไปด้วย
  - ไฟล์สำรองแบบเก่า (ไม่มีไฟล์แนบ) ยังนำเข้าได้ปกติ ระบบรองรับทั้งสองแบบ

## อัปเดตล่าสุด

- **สีป้ายหมวดหมู่แยกกันชัดเจนขึ้น** — เดิมสีบางหมวดซ้ำกันจนดูเหมือนเป็นสีทองหมด แก้ให้มี 12 สีที่แยกจากกันชัดเจน และคำนวณสีให้กระจายตัวดีขึ้น
- **ตั้งไอคอนเองต่อหมวดหมู่ได้แล้ว** — หน้า "จัดการหมวดหมู่" กดปุ่มไอคอนหน้าชื่อหมวด เลือกได้จาก ~20 แบบ (มีแยกสำหรับเกมยิง / เกม MOBA / เครื่องคอนโซล / ธนาคาร / ช้อปปิ้ง ฯลฯ) ไอคอนที่ตั้งจะโชว์ทั้งที่ป้ายหมวดหมู่, ช่องกรองด้านบน และไอคอนหน้ารายการ ช่วยแยกเกม/บริการที่คล้ายกันให้ดูออกไวขึ้น ถ้าไม่ตั้งเอง ระบบยังเดาไอคอนให้อัตโนมัติจากชื่อ platform เหมือนเดิม
- **ช่องกรองหมวดหมู่โชว์จำนวนรายการ** เช่น "เกม (12)" ให้รู้ทันทีว่าหมวดไหนมีของเยอะ
- **ปุ่มคัดลอกรหัสผ่านด่วน** อยู่ที่แถวรายการเลย ไม่ต้องเปิดรายละเอียด → กดแสดง → กดคัดลอก อีกต่อไป (เฉพาะรายการที่เป็นพาสเวิดและมีรหัสผ่านบันทึกไว้)
- ชื่อผู้พัฒนา "Alexander_Weng" ที่ท้ายหน้าเด่นขึ้นกว่าคำว่า "Developed by"
- ค่า icon_key ของหมวดหมู่ **ไม่ได้เข้ารหัส** (เก็บแค่ชื่อไอคอนทั่วไป เช่น "controller" ไม่ใช่ข้อมูลส่วนตัว) ต่างจากชื่อหมวดหมู่ที่เข้ารหัสอยู่เหมือนเดิม

## ทดสอบก่อนใช้จริง

แนะนำให้ลองสร้างบัญชีทดสอบ เพิ่ม-แก้-ลบรายการ ลองแนบไฟล์ ลอง export/import ดูก่อน ค่อยเอาข้อมูลจริงเข้าไป
